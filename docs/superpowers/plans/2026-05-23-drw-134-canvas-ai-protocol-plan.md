## TL;DR

Доставляем bidirectional protocol для AI/canvas в три фазы: (1) **identity + meta types** (foundation, internal milestone, ships вместе с Phase 2), (2) **read/write API + MCP tools + frontend mermaid-import rewrite** (shipping core), (3) **frame duplication + delete + UI picker + storage-only hardening**. Итого 17 atomic tasks (~6 / ~8 / ~3), ориентир ~40–50 часов работы subagent'ов; финальный release — `0.23.0` после Phase 3.

## Phasing recap (из spec §Phasing)

- **Phase 1 (foundation, internal milestone):** identity generator (`<slug>-<6char>` / `e-<6char>`), TypeScript типы для `SchemaFrameMeta` / `SchemaChildMeta` / `OverlayEntry` / `RoomMetaV2`, room-level `didrawProtocol` marker detection, regex validator. Тесты unit-level; runtime поведение не меняется. Ship'ится вместе с Phase 2 как часть `0.23.0` (см. spec §Phase 1 shipping status).
- **Phase 2 (shipping core):** `GET /api/canvas/view` (polymorphic v1/v2), `POST /api/schema/create` (snapshot — `raw` или `actions`), `POST /api/schema/{frameId}/patch` (incremental), `POST /api/schema/{frameId}/overlay` shortcut, mermaid storage-mode parser (graph/flowchart subset из mapping table), MCP tools (`shemma_canvas_view`, `shemma_create_schema`, `shemma_patch_schema`, `shemma_set_overlay`), frontend mermaid-import rewrite (write protocol marker + assign identity + auto-ungroup), frontend overlay-sync listener (user drag → POST overlay). DRW-127 (storage-only) автоматически закрывается.
- **Phase 3 (hardening):** `POST /api/schema/{frameId}/duplicate` (frame duplication + ID remap), `DELETE /api/schema/{frameId}`, `shemma_duplicate_schema` + `shemma_delete_schema` MCP tools, Cmd-Shift-K UI picker для optional role/connectionKind на user-drawn shapes, storage-only E2E verification (без браузера). Финальный release commit + tag `0.23.0`.

```typescript
export type NodeId = string;

/** Slug normalization per spec §Identity format formal:
 *  1) lowercase, 2) [^a-z0-9]+ → '-', 3) trim '-', 4) slice 40 chars, 5) fallback "shape". */
export function slugify(label: string): string;

/** Regex builder для конкретного suffix-length. */
export function nodeIdRegex(suffixLen: number): RegExp;

/** Default regex (suffixLen=6). */
export const DEFAULT_NODE_ID_REGEX: RegExp;

export const SUFFIX_LENGTH_MIN = 3;
export const SUFFIX_LENGTH_MAX = 12;
export const DEFAULT_SUFFIX_LENGTH = 6;

/** Generate random base36 suffix. RNG injectable для deterministic tests.
 *  `rng()` должна возвращать [0,1). Default: Math.random.
 *  Backend будет инжектить crypto-based RNG в Task 1.2. */
export function generateSuffix(suffixLen: number, rng?: () => number): string;

/** Generate full NodeId с retry × 8 при collision.
 *  Throws Error("nodeId-collision") если все 8 attempts collide. */
export function generateNodeId(opts: {
  slug: string;                              // empty / "shape" → anonymous form "e-<6char>"
  suffixLen?: number;                        // default 6
  existingIds: ReadonlySet<NodeId>;
  rng?: () => number;
}): NodeId;

/** Validate ID matches `nodeIdRegex(suffixLen)`. */
export function isValidNodeId(id: string, suffixLen?: number): boolean;
```

## Task 1.2 — Add backend-side identity wrapper с crypto RNG

**Goal:** обернуть `@shemma/domain` identity API в backend-specific module, который использует `crypto.randomBytes` вместо `Math.random` (спека требует server-side strong RNG; frontend может оставаться на Math.random).

**Files:** [NEW]
- `apps/backend/src/domain/schema/identity.ts`
- `apps/backend/src/domain/schema/identity.test.ts`

**Diff size estimate:** ~60 LOC new + ~40 LOC tests.

**Dependencies:** Task 1.1 (uses `generateNodeId` + `slugify` из `@shemma/domain`).

**Implementation:**

```typescript
import { randomBytes } from "node:crypto";
import { generateNodeId, slugify, type NodeId, DEFAULT_SUFFIX_LENGTH } from "@shemma/domain";

/** Crypto-based RNG returning [0,1). */
function cryptoRng(): number {
  // 4 bytes → uint32 → divide by 2^32 для [0,1).
  return randomBytes(4).readUInt32BE(0) / 0x1_0000_0000;
}

export function generateNodeIdServer(opts: {
  slug: string;
  suffixLen?: number;
  existingIds: ReadonlySet<NodeId>;
}): NodeId {
  return generateNodeId({ ...opts, rng: cryptoRng });
}

/** Convenience: derive NodeId from label. Slugifies first. */
export function nodeIdFromLabel(label: string, existingIds: ReadonlySet<NodeId>, suffixLen?: number): NodeId {
  return generateNodeIdServer({ slug: slugify(label), existingIds, suffixLen });
}

export { slugify, isValidNodeId, nodeIdRegex } from "@shemma/domain";
```

**Tests:**
- `generateNodeIdServer({slug:"api", existingIds: new Set()})` returns valid NodeId matching `nodeIdRegex(6)`.
- 1000 sequential calls produce 1000 unique IDs (collision rate sanity check, see spec §Risks#4 birthday paradox math).
- `nodeIdFromLabel("Auth Service", new Set())` starts with `"auth-service-"`.
- `nodeIdFromLabel("", new Set())` starts with `"e-"` (empty label → empty slug → anonymous form per Task 1.1 contract).

**Acceptance:**
```bash
bun --cwd apps/backend test src/domain/schema/identity.test.ts
# Expected: 4 tests pass.
```

**Notes/risks:**
- Не использовать `Math.random()` на backend — sufficient entropy critical для production-grade IDs.
- Этот module — единственная точка где backend знает о RNG; downstream code (apply, duplicate) импортирует только `generateNodeIdServer` / `nodeIdFromLabel`.

```typescript
import type { RoomState } from "../../types";
import { DEFAULT_SUFFIX_LENGTH, SUFFIX_LENGTH_MIN, SUFFIX_LENGTH_MAX } from "@shemma/domain";

export function isV2Room(room: RoomState | undefined | null): boolean {
  return room?.meta?.didrawProtocol === "v2";
}

/** Returns valid suffix length, clamped to [MIN, MAX]. */
export function roomSuffixLength(room: RoomState | undefined | null): number {
  const raw = room?.meta?.didrawIdSuffixLength;
  if (typeof raw !== "number" || !Number.isInteger(raw)) return DEFAULT_SUFFIX_LENGTH;
  if (raw < SUFFIX_LENGTH_MIN) return SUFFIX_LENGTH_MIN;
  if (raw > SUFFIX_LENGTH_MAX) return SUFFIX_LENGTH_MAX;
  return raw;
}
```

**Tests:**
- `isV2Room(undefined)` === false.
- `isV2Room({ meta: undefined } as never)` === false.
- `isV2Room({ meta: { miroExports: {} } } as never)` === false.
- `isV2Room({ meta: { didrawProtocol: "v2" } } as never)` === true.
- `roomSuffixLength(undefined)` === 6.
- `roomSuffixLength({meta:{didrawIdSuffixLength:8}} as never)` === 8.
- `roomSuffixLength({meta:{didrawIdSuffixLength:2}} as never)` === 3 (clamp to MIN).
- `roomSuffixLength({meta:{didrawIdSuffixLength:99}} as never)` === 12 (clamp to MAX).
- `roomSuffixLength({meta:{didrawIdSuffixLength: 6.5 as never}} as never)` === 6 (non-integer fallback).

```typescript
import type { RoomState } from "../../types";
import type { TLRecord } from "../../store-types";
import { richTextToString } from "../context";
import type { CanvasViewResponse, OverlayEntry } from "@shemma/domain";

export function buildCanvasView(room: RoomState): CanvasViewResponse {
  const records = room.store.store ?? {};
  const frames: CanvasViewResponse["frames"] = [];
  const free: CanvasViewResponse["free"] = [];

  for (const id in records) {
    const r = records[id] as TLRecord | undefined;
    if (!r || r.typeName !== "shape") continue;
    const meta = r.meta as { didrawSchemaFrame?: unknown } | undefined;
    if (meta?.didrawSchemaFrame === true) {
      frames.push(buildFrameEntry(r, records));
    } else if (isPageChild(r, records)) {
      // isPageChild = ancestry walk до page-record; reject if any ancestor
      // имеет meta.didrawSchemaFrame === true.
      free.push(buildFreeEntry(r));
    }
    // shapes inside frames — not in either list (their content captured via frame.raw)
  }

  return { schemaVersion: "v2", frames, free };
}

// helpers:
// - buildFrameEntry: read meta.mermaidSource → raw, meta.didrawOverlays → overlays,
//   compute bbox via union of children OR frame's own props.w/h fallback (spec §bbox computation).
// - isPageChild: shape NOT descendant of any didrawSchemaFrame. Реализация через
//   ancestry walk: подняться по `parentId` цепочке; если встретили shape с
//   meta.didrawSchemaFrame === true → false; если parentId указывает на page
//   record (`parentId.startsWith("page:")` ИЛИ записи с typeName === "page") →
//   true. Не hardcode'ить "page:page" — multi-page rooms имеют другие page id.
//   Cycle guard: max 64 hops, ассертить против infinite loop.
// - buildFreeEntry: id + type + label (richTextToString) + bbox.
```

Steps per spec §Write semantics §Apply flow:
1. Parse `frame.meta.mermaidSource` → oldActions.
2. Validate each action against current state: `unknown-node` / `duplicate-node` / `invalid-id` / `invalid-role` / `invalid-connection-kind`. Collect errors; if any → return `{ok:false}` без mutation.
3. Apply actions sequentially к in-memory action list → newActions.
4. Generate new RAW via Task 2.3 generator.
5. Re-parse new RAW (sanity) → if fails → `{ok:false, errors:[{code:"invalid-mermaid"}]}`.
6. Build diff via `diffSchemas`.
7. Translate diff → `StoreChangeBatch` (added shapes → `batch.added`, removed → `batch.removed`, renamed/role-changed → `batch.updated`).
8. Apply existing overlays from `frame.meta.didrawOverlays` to new shapes (positions, colors).
9. Count `orphanedOverlays` = entries для removed NodeIds.
10. Compute `destructiveScore = removedCount / oldNodeCount` (avoid div-by-zero).
11. Return result. **Не** committ'ить в room.store — это callers responsibility (route handler).

Rollback discipline (spec §Write semantics §Rollback order):
- `oldRaw` + `oldOverlays` snapshot держится до return.
- Parse failure step 5 → rollback (just return error, no mutation).

1. Resolve room + v2 check.

4. Call `applySchemaActions` (Task 2.4).
5. On success — persist batch + new `meta.mermaidSource` + new `meta.didrawOverlays`; emit WS; return `{ok:true, frameId, version, orphanedOverlays, addedNodeIds, removedNodeIds, destructiveScore}`.

## Risks & mitigations

1. **Mermaid bespoke parser misses edge cases.** Spec §Risks#1 + plan Task 2.2 explicitly notes fallback на `@mermaid-js/parser` library if real-world samples break parsing. **Mitigation:** start с bespoke (Option A); if Task 2.4 integration tests reveal quoted-label / multiline failures — open mid-Phase escalation, switch to Option B before final release. Adds ~2-3h.

2. **LLM hallucination на patch (`unknown-node`).** Spec §Risks#2. **Mitigation:** explicit AI guidance в `shemma_patch_schema` tool description (Task 2.8): "ALWAYS call shemma_canvas_view immediately before patch to get current NodeIds; do not patch from cached knowledge." Idempotency cache (Task 2.5) protects against double-apply.

3. **Atomic apply rollback bugs.** Spec §Write semantics §Rollback order — invariant: новый RAW не commit'ится до successful parse + diff + batch construct. **Mitigation:** Task 2.4 explicitly tests «3 actions, 2nd invalid → RAW unchanged»; Task 2.5 layer тестирует через HTTP integration.

4. **Frontend overlay-sync infinite loop.** User drag → POST → backend emits WS → frontend store update → could potentially trigger overlay-sync again. **Mitigation:** Task 2.7 filter `source: "user"` excludes backend-originated updates (source: "remote"). Tests cover this.

5. **Backward incompat for callers of `shemma_context`.** Spec §MCP callers migration guide enumerates 3-step migration. **Mitigation:** Task 2.8 keeps `shemma_context` polymorphic — v1 rooms get byte-identical legacy shape, v2 rooms get new + warning. CHANGELOG documents removal milestone (Task 3.4 release prep).

6. **CLAUDE.md identity invariant drift.** Plan §Task 3.4 explicit edit. **Mitigation:** review checklist includes verifying CLAUDE.md updated before tag.

7. **Phase 2 task count overrun.** 8 tasks is upper end of single-phase comfort. **Mitigation:** Tasks 2.2 and 2.3 (parser + generator) могут идти параллельно different subagents через `dispatching-parallel-agents` skill if координатор spawn'ит обе concurrently.
