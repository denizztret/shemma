# Layout Фаза 3 — роутинг рёбер (DRW-199): libavoid-as-layout-hint — Design

**Status:** v1.1 — реализовано (execution 2026-06-12); §12 — отклонения по факту
**Author:** Claude (with user)
**Branch:** `feature/drw-199-arrow-routing`
**Входы:** спайк DRW-244 ([отчёт](../../references/drw-244-spike/report.md)), probe иерархии ([drw-199-probes](../../references/drw-199-probes/results.txt)), portHints Фазы 2, эталоны юзера
**Предшественники:** Фаза 1 (DRW-218/233), Фаза 2 (DRW-235)

## 1. Цель и принятые решения

После явной компоновки (⌘⇧L / ⌘⌥⇧L) стрелки не идут сквозь боксы и не переплетаются
на выходе из узла. AI-правки и ручное редактирование по-прежнему ничего не перекладывают
(no-auto-layout инвариант не трогаем).

Решения юзера (brainstorm 2026-06-12, зафиксированы):

| Вопрос | Решение |
|---|---|
| Движок | **libavoid-as-layout-hint + штатные elbow-стрелки** (вердикт спайка DRW-244 принят; runtime custom shape отклонён) |
| Охват рёбер | **Все рёбра scope'а, внедрение поэтапно** (межконтейнерные → live-проверка → все), метрик-гейт против деградации |
| Размещение | **Frontend-пайплайн** (как Ф1/Ф2); backend-паритет — расширение DRW-245 |
| Детуры (невыразимые маршруты) | **Лучшее приближение + метрика «невыразимости»**; пере-размещение узлов под маршрут — отдельная следующая фаза по данным метрики |
| Порты | **Libavoid выбирает пины** из сетки exclusive-позиций на сторонах; выбор пишется в binding'и |

Acceptance-эталоны:
- `docs/superpowers/specs/assets/2026-06-12-drw235-etalon-before/-ideal.png` — ребро A3→E2
  обходит схему коридором, не сквозь C2/C3 (см. §5 об ограничении выразимости).
- Репро ADV-4255 — пучок стрелок из одного узла не переплетается на выходе.

## 2. Probe-результаты, определившие архитектуру (2026-06-12)

Headless-пробы на реальной геометрии комнат `drw-235-probe` (t218, 19 боксов / 12 рёбер)
и `drw-235-probe2` (CI-схема, v2-фрейм, 22 бокса / 20 рёбер); скрипты и вывод —
`docs/references/drw-199-probes/`.

**Находка 1 (критическая): libavoid требует непересекающихся препятствий.**
Наивные модели — «все боксы препятствия» (V-A), «только листья» (V-B), «per-class
исключение предков, но контейнеры с детьми» (V-F) — все дают маршруты СКВОЗЬ контейнеры
(A3→E2 через C3; fastlane→distribute через kmp-mac): вложенные боксы (дети внутри
контейнеров) ломают orthogonal visibility-граф libavoid. Минимальные кейсы без вложенности
обходятся идеально — проблема именно в overlap.

**Решение — V-H, «иерархическая видимость per-class»: violations = 0 на обеих комнатах.**
- Рёбра группируются в классы по множеству предков-контейнеров обоих концов.
- Для класса набор препятствий строится без overlap: предки концов «раскрываются» до своих
  детей (контейнер не препятствие, его дети — да), все остальные контейнеры — опаковые
  боксы (их дети НЕ добавляются), свободные листья — как есть.
- Один Router на класс; 7 классов на обеих probe-комнатах, суммарно 4-5 мс.

**Находка 2: у same-side U-маршрутов tldraw нет управляемого midpoint.**
В каталоге elbow-роутера (`elbowArrowRoutes.tsx`) `midpointHandle` есть только у Z-форм
(разные стороны, средняя линия `midX`/`midY`); симметричные U-формы (`to right 1` и т.п.)
строятся на фиксированной глубине `common.expanded` (юнион двух концевых боксов + leg)
без ручки. Следствие: U-детур, чья глубина продиктована ЧУЖИМИ боксами (эталон A3→E2:
bottom→bottom U на y=547 ниже C3), штатной стрелкой точно невыразим — see §5.

## 3. Архитектура пасса

Новый финальный пасс пайплайна компоновки (после Ф2-выравнивания/обтяжки/re-pack),
frontend, новый модуль `apps/frontend/src/canvas/edge-routing.ts` + чистое ядро.

```
runEdgeRoutingPass(input):
  вход: боксы scope'а (абсолютные, после Ф2), рёбра (from/to/arrowId),
        portHints Ф2, пины/locked, направление фрейма
  1. классификация рёбер (V-H): класс = sorted(предки(from) ∪ предки(to))
  2. для каждого класса:
       Router(OrthogonalRouting), shapeBufferDistance, idealNudgingDistance,
       nudgeOrthogonalSegmentsConnectedToShapes
       препятствия = visibleSetFor(класс)        // §2, без overlap
       пины: сетка exclusive-позиций по сторонам концевых боксов
       ConnRef per ребро → processTransaction → полилинии
  3. глобальная раздача позиций портов (§4): стороны и порядок — из маршрутов,
     позиции на стороне — равномерная сетка с сохранением порядка
  4. перенос в штатные стрелки (§5): стороны → binding, mid-line → elbowMidPoint;
     детуры → лучшее приближение (включая arc-кандидата)
  5. метрик-гейт (§6): хуже текущего → ребро не трогаем
  выход: writeback-план (bindings + props) + отчёт пасса {expressible, approximated,
         skipped, метрика невыразимости}
```

Ядро (классификация, visibleSet, перенос, гейт-метрики) — чистые функции без tldraw/editor
(юниты в bun); libavoid-обёртка и writeback — тонкий слой. WASM грузится лениво при первом
вызове пасса; не загрузился → пасс пропускается (текущее поведение, console.warn).

Существующие `optimizeElbowMidpoints`/`optimizeScopedElbows` остаются fallback-механизмом
(нет WASM) и убираются из основного пути там, где их заменяет новый пасс.

### Иерархия и portHints

V-H работает с любой глубиной вложенности (раскрытие рекурсивно). portHints Фазы 2
(точки выровненных рёбер на границах контейнеров) используются как **подсказки стоимости**:
пины вблизи portHint получают пониженный `setConnectionCost` — выровненные Ф2 рёбра
сохраняют свои прямые линии (идемпотентность с Ф2), libavoid не переизобретает их маршрут.

## 4. Порты

- Сетка пинов: k exclusive-позиций на каждой стороне концевого бокса
  (k = max(2, ceil(степень узла / 2)), позиции `(i+1)/(k+1)`), `ConnDirFlags` стороны.
- Libavoid выбирает пин per-ребро в рамках класса (exclusive ⇒ внутри класса пины
  не сливаются; nudging разводит параллельные сегменты).
- Классы независимы ⇒ возможен конфликт «два ребра разных классов выбрали один пин».
  Финальный шаг — глобальная раздача: на каждой стороне узла собираются все рёбра
  (со сторонами и направлениями выхода из маршрутов), упорядочиваются по позиции
  соседнего сегмента маршрута и получают позиции `(i+1)/(n+1)` — порядок маршрутов
  сохраняется, переплетение на выходе исчезает (закрывает ADV-4255).
- Writeback: `normalizedAnchor` + `isPrecise: true` + `snap` — тот же механизм, что
  текущий `distributeArrowPorts` (DRW-172), который этим пассом замещается в scope'е
  роутинга.

## 5. Перенос маршрута в штатную стрелку

По убыванию точности:

1. **Прямая / L (1-2 сегмента):** стороны из первого/последнего сегмента; midpoint
   дефолтный. Точный перенос.
2. **Z-форма (3 сегмента, разные стороны):** стороны + `elbowMidPoint` из положения
   средней линии (нормирован между концевыми боксами). Точный перенос, пока средняя
   линия в диапазоне ручки tldraw.
3. **Same-side U (3 сегмента, одна сторона)** с глубиной, продиктованной чужими боксами, —
   точно невыразим (§2, находка 2). Кандидаты приближения:
   a. U со штатной глубиной (стороны верные, глубина дефолтная);
   b. **arc-кандидат**: `kind:"arc"` + вычисленный `bend` (единственный per-arrow
      контролируемый параметр кривизны) — дуга, очищающая препятствия; проверяется
      сэмплированием против боксов;
   c. Z-приближение по ближайшей паре сторон.
   Гейт (§6) выбирает лучший из кандидатов И текущего маршрута.
4. **Детуры 4+ сегментов:** те же кандидаты (a-c); как правило остаётся текущий маршрут
   + метрика.

Каждое приближённое/пропущенное ребро попадает в отчёт пасса с метрикой невыразимости
(сколько чужих боксов пересекает лучший достижимый вариант vs маршрут libavoid). Метрика —
вход следующей фазы (локальный VPSC-пуш узлов, открывающий коридоры; **вне scope Ф3**).

**Честное следствие для эталона A3→E2:** его идеальный коридор (y ниже C3) штатно
невыразим. Достижимый исход Ф3 — arc-обход (если гейт пропустит) либо ребро остаётся
как есть с пометкой. Полное соответствие -ideal.png достигается следующей фазой
(пере-размещение). AC#1 сформулирован соответственно.

## 6. Метрик-гейт (no-surprise)

Для каждого ребра считаются (чистые функции, переиспользуют `countBoxOverlaps`-подход
direction-choice):
- пересечения маршрута с чужими боксами (вес 1.0);
- пересечения ребро-ребро в scope (вес 0.15);
- длина маршрута (тай-брейк).

Кандидат применяется только при строгом улучшении против текущего фактического маршрута
ребра (анти-дрейф, как `pickDirectionCandidate`). Пины/`styleOwnedBy:user`/locked —
не трогаются (writeback пропускает). Идемпотентность: повторный пасс на свёрстанной
схеме = пустой дифф (libavoid детерминирован — подтверждено спайком; раздача портов
детерминирована сортировкой).

## 7. Scope и не-цели

**In scope:** пасс edge-routing (V-H + пины + перенос + гейт), интеграция в
`autoLayoutFrame`/container-scope после Ф2-пасса, замещение `distributeArrowPorts`
в зоне действия, lazy-WASM (Vite alias для prod-сборки — грабля спайка), отчёт пасса,
эталоны live.

**Out of scope:** пере-размещение узлов под маршруты (следующая фаза, по метрике);
backend parity (DRW-245); runtime re-route при drag (native binding как есть);
кастомный arrow-shape (отклонён); UI поверх отчёта пасса.

## 8. Тест-план

- **Юниты (bun):** классификация V-H + visibleSet (вложенность 2+ уровней);
  segment-vs-box пересечения; перенос (Z-midpoint нормировка, выбор кандидата детура);
  глобальная раздача портов (порядок из маршрутов, детерминизм); гейт (строгое улучшение).
- **Headless-харнесс** (расширение drw-199-probes): обе probe-комнаты — violations 0
  у переносимых, отчёт по детурам, идемпотентность двух прогонов.
- **Live (координатор, chrome-devtools):** AC#1-7.

## 9. Acceptance Criteria

1. Эталон A3→E2 (drw-235-probe): ребро либо визуально обходит C2/C3 (arc-кандидат),
   либо помечено метрикой невыразимости в отчёте пасса; остальные 11 рёбер — без
   пересечений с боксами. Маршруты не хуже текущих (гейт).
2. CI-схема (drw-235-probe2): 0 новых пересечений ребро-бокс после ⌘⌥⇧L;
   выровненные Ф2 линии не разрушены (portHints-стоимости работают).
3. Пучок из одного узла (репро ADV-4255 или синтетика ≥3 рёбер из узла) не переплетается
   на выходе; порядок портов соответствует порядку целей.
4. Идемпотентность: повторный ⌘⇧L на свёрстанной схеме — пустой дифф.
5. Детерминизм: два прогона с нуля — идентичный результат.
6. Пины (`meta.pinned`), locked-фреймы, `styleOwnedBy:user` не тронуты; locked-эталоны
   a-elk-tree/dl-test нетронуты.
7. Prod-сборка Vite собирает и грузит wasm (alias/asset — решение задокументировано);
   деградация без WASM = текущее поведение.

## 10. Этапность (для плана)

T1 probe-харнесс ядра (классы/visibleSet/метрики на probe-комнатах) → T2 ядро переноса +
юниты → T3 libavoid-обёртка + lazy-load + Vite alias → T4 интеграция в пайплайн за
dev-флагом → T5 порты (сетка пинов + глобальная раздача) → T6 метрик-гейт + отчёт пасса +
детур-кандидаты (включая arc) → T7 live-верификация эталонов координатором → T8 закрытие
(CHANGELOG, AC, флаг долой). Live-проверки итеративно по ходу (политика юзера), не только в T7.

## 11. Риски

- **Range-ручки midpoint в tldraw**: нормировка `elbowMidPoint` может не совпасть с нашей
  моделью средней линии — T2 закрывает юнитом против фактического рендера (live-сверка в T4).
- **Arc-кандидат**: дуга может задевать углы боксов (проверка сэмплированием консервативна);
  гейт отбрасывает плохие дуги — это деградация к «помечено метрикой», не дефект.
- **Производительность**: per-class роутеры на больших досках (50+ контейнеров) —
  probe показал ~5 мс/7 классов; бюджет пасса < 200 мс, иначе батчинг классов.
- **Конфликт с auto-direction Ф1**: пасс выполняется ПОСЛЕ выбора направлений и не меняет
  позиции боксов — пересечения по построению нет.

## 12. v1.1 — отклонения и находки реализации (2026-06-12)

1. **Aligned-рёбра Ф2: общий гейт вместо portHints-стоимостей (§3).** Безусловное сохранение
   выровненных рёбер оказалось неверным: эталонное ребро A3→E2 САМО aligned (Ф2 выровняла его
   концы), и skip сохранял дефект (live T5). Реализация: aligned-рёбра роутятся наравне со всеми,
   их прямая линия защищена гейтом (foreign=0 → кандидат не лучше → линия остаётся);
   `alignedKept` в отчёте = aligned-рёбра, сохранённые гейтом.
2. **WASM-URL:** `new URL("../../node_modules/libavoid-js/dist/libavoid.wasm", import.meta.url)`
   — работает в Vite dev, prod-build (ассет `libavoid-*.wasm` в dist) и bun-тестах; alias не понадобился.
3. **Arc-модель — точная круговая дуга.** Две live-находки: (а) `bend` tldraw — сагитта
   (середина дуги отклоняется на bend, Безье-модель с apex=bend занижала вдвое); (б) даже
   исправленная Безье расходится с круговой формой между серединой и концами — реальная дуга
   задевала бокс при «чистой» модели. Итог: сэмплирование точной окружности (R = s/2 + L²/8s)
   + клиренс 4px в проверке. Множители кандидатов bend расширены до ±[1,1.5,2,2.5,3,4]·d
   (отклонение дуги в точке препятствия ≈ 2t(1-t)·bend — вне центра хорды нужен запас).
4. **Метрика видит кривые.** `foreignCrossings` дополнен проверкой вершин внутри бокса:
   текущая геометрия arc-стрелок — диагональные сегменты, ortho-only метрика была слепа
   к грязным дугам (гейт считал их чистыми). Плюс `ORTHO_EPS=0.5` — вершины реальных стрелок
   имеют float-дрейф (Δy≈0.01), строгое равенство прятало пересечения прямых.
5. **Scope рёбер — по концам** (инвариант `distributeArrowPorts`: byArrow покрывает весь store,
   стрелки в scope-набор не входят).
6. **Флаг снят (T8):** пасс работает по умолчанию; opt-out `window.__SHEMMA_EDGE_ROUTING = false`;
   деградация без WASM — прежняя пара distributeArrowPorts + optimizeScopedElbows.
7. **Live-итоги AC:** #1 — 12/12 рёбер эталона без пересечений (A3→E2 — дуга, bend≈171);
   #2 — CI-схема 19/20 чисто, 1 узкий детур невыразим дугой (foreignBest=2, помечен метрикой —
   вход фазы пере-размещения), «0 новых» выполнено; #3 — синтетика «хаб+3»: 2 перехлёста → 0,
   порты в порядке целей; #4 идемпотентность (пустой дифф); #5 детерминизм (идентичные прогоны);
   #6 конструктивно (пасс не двигает боксы, не пишет стиль); #7 prod-сборка несёт wasm.
8. **Сужение §5.3 (phase-end review):** из кандидатов детура реализован только arc (b);
   «U со штатной глубиной» (a) и «Z-приближение» (c) — осознанный follow-up: live AC прошли
   без них, гейт защищает от деградации, метрика невыразимости покажет, нужны ли они.
9. **Фиксы phase-end review (commit 90ec424):** пины по степени узла
   (`maxEndpointDegree`, спека §4 выполнена с запасом max(3, degree)); residual-порты —
   classification-skipped рёбра (лист→свой контейнер) получают старый `distributeArrowPorts`
   по подмножеству byArrow (поле `unrouted` в отчёте); lifecycle WASM-объектов
   (try/finally + удаление temps, пасс при исключении деградирует к elbow-пассу);
   `elbowMidPoint: 0.5` пишется явно для straight/L (анти-stale); writeback выделен в чистую
   `buildWritebackPlan` + 4 юнита.
10. **Приёмочные фиксы (dl-test, 2026-06-13, коммиты 6e1fabc/ff16484/9ca1137):**
   (а) **flow-aware пины**: ребро, чьи концы разделены вдоль оси потока, обязано входить/
   выходить по сторонам вдоль потока — семантика старого sideOf возвращена через ЖЁСТКИЕ
   классы пинов (PIN_ALONG/PIN_CROSS per-терминал по separatedAlongAxis); мягкий cost не
   работал (выигрыш длины бокового входа перевешивал штраф). Ось узла: meta.didrawDirection
   контейнера-родителя (props.direction вырождается в "custom" — канон НЕ он) → fallback
   направление scope (flowDir с call-site). Гейт согласован: RouteMetrics.crossFlow
   (вес 0.1) штрафует поперечный терминал только у разделённых пар — same-layer рёбра
   легально ходят боком и не выдавливаются в детуры.
   (б) **pinned-контейнер обтягивается**: позиционный пин больше не блокирует w/h-writeback
   контейнера во фрейм-пассе — его дети переразложены этим же пассом и без обтяжки
   вылезали из не-обжатого бокса (это Ф1-зона, найдено приёмкой Ф3); размер охраняет
